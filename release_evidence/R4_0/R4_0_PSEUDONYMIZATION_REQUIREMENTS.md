## Purpose

Define pseudonymization requirements for the eHospital research data boundary. Pseudonymization is the technical control that allows research use of clinical data without exposing patient identity.

---

## 1. Pseudonymization model

| Property | Requirement |
|---------|-------------|
| Algorithm | SHA-256(real_id ‖ institutional_salt) |
| Output format | 64-character lowercase hex string |
| Salt | Generated by institutional key vault (NOT stored in Research OS) |
| Reversibility | NOT directly reversible without salt + original ID |
| Storage | Pseudonymized ID only in Research OS; real ID in participant ID log (off-system) |
| Re-identification | Only possible with institutional key vault access + audit trail |

---

## 2. What is pseudonymized

| Data element | Treatment |
|-------------|----------|
| Patient real ID / MRN | → SHA-256 pseudo_id |
| Full name | BLOCKED — must not enter Research OS |
| Date of birth | BLOCKED — use age_group (5-year bands) |
| Address | BLOCKED |
| Phone / email | BLOCKED |
| NHI / national ID | BLOCKED |
| Diagnosis codes (ICD-10) | RETAINED — non-identifying |
| Procedure codes | RETAINED — non-identifying |
| Laboratory values | RETAINED — non-identifying |
| Dates (admission/discharge) | SHIFTED — if required; or time interval only |

## 3. PII key guard (implemented in ExtractRecord)

`ExtractRecord.__post_init__` rejects any record whose `data` dict contains keys from the PII blocklist:
```
name, full_name, first_name, last_name, date_of_birth, dob, birth_date,
address, street, city, postal_code, phone, mobile, telephone,
email, national_id, nhi, passport, mrn, hospital_number
```
→ raises `ValueError("ExtractRecord.data contains potential PII keys: ...")`
